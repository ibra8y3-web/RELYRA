هذا الجرد يفرق بين وجود الكود، اختبارات الوحدات، اختبارات التكامل، والتشغيل على أجهزة فعلية. لا يُعد نجاح البناء دليلًا على تشغيل شبكة عامة أو توافق هاتفين مستقلين.

## 1. الموجود فعليًا في main

### تطبيق Android والهوية والتخزين
- تطبيق Kotlin/Jetpack Compose مع موارد عربية RTL وإنجليزية.
- هوية محلية Ed25519 وبطاقات اتصال موقعة وQR/روابط ومفتاح استرداد.
- Room وSQLCipher، ومفتاح قاعدة البيانات محمي بواسطة Android Keystore، وقفل بيومتري/بيانات اعتماد الجهاز.
- رسائل فردية باستخدام X3DH وDouble Ratchet، وصندوق إرسال دائم، ACK، إعادة محاولة/backoff ومنع التكرار.
- WorkManager وخدمة اتصال أمامية اختيارية.

### المجموعات وMLS
- المجموعات القديمة تستخدم إرسالًا منفصلًا مشفرًا لكل عضو عبر Double Ratchet.
- المجموعات الجديدة تستخدم OpenMLS 0.9.2 عبر Rust/JNI وقاعدة SQLCipher منفصلة.
- توجد KeyPackage وWelcome وCommit وApplicationData، إضافة/إزالة أعضاء وحفظ epochs.
- طلبات تغيير العضوية من المشرفين تمر عبر المالك، والمالك وحده يكتب Commit/epoch لتجنب الكتابات المتنافسة.
- مرفقات المجموعة: وصف المرفق داخل MLS ApplicationData، والملف المشفر عبر Blossom.
- إيصالات قراءة المجموعة موجودة كرسائل تحكم RELYRA مصادق عليها لكل نسخة مستلم؛ ليست جزءًا من MLS ApplicationData.

### الشبكة والنقل
- Nostr عبر WSS يختاره المستخدم.
- WebRTC P2P DataChannel مع إشارات موقعة وموافقة المستخدم على العروض الواردة؛ لا توجد MediaTracks للمكالمات.
- خدمة Go/libp2p Kademlia DHT مستقلة مع Pebble وHTTPS gateway وPresence API.
- إعداد coturn وREST credentials مؤقتة موقعة.
- تطبيق Android يتصل ببوابة HTTPS، وليس libp2p host داخل الهاتف.
- Bluetooth Classic للأجهزة المقترنة مسبقًا، Wi-Fi Direct وNearby LAN مع مصافحة متبادلة لهوية Ed25519 لجهات الاتصال المعروفة.

### المجتمعات
- خدمة اكتشاف Go وعميل Android.
- manifests ودعوات وإثباتات وصول وعضوية وحظر/إلغاء حظر.
- منشورات موقعة وتسلسل لكل مؤلف ومنع التكرار.
- أحداث إشراف موقعة، وتقارير وسجل تدقيق وشاشات مشرف.
- مسار النشر يفرض ban/mute/slow-mode/allow-post.
- **قيد خصوصية مهم:** نص المنشور مخزن حاليًا كنص صريح في خدمة الاكتشاف؛ التوقيع لا يعني تشفيرًا طرفيًا.

### الملفات والنسخ والأدوات
- Blossom لرفع ciphertext وتنزيله؛ تنزيل HTTP Range قابل للاستكمال مع فحص الحجم وSHA-256. الرفع الحالي ليس رفعًا مجزأ قابلًا للاستكمال.
- Vault محلية مشفرة، وWebView محدود، وقارئ PDF للقراءة فقط، وأدوات فحص الملفات والتشخيص وقياس موارد التطبيق.
- BackupManager يضم قاعدة البيانات وVault وinbox/outbox وMLS وإعدادات الشبكة/الخوادم القابلة للنقل. يتحقق من الملفات المشار إليها، الأحجام والبصمات، ويفك تحقق Vault، ويجهز الاستعادة قبل تبديل البيانات.
- الاستعادة تمسح جلسات Ratchet وحزم التشفير ومفاتيح X3DH أحادية الاستخدام القديمة وتمنع إعادة استعمال حالة تشفير قديمة.

## 2. النواقص التي لا يجوز إعادة بنائها من الصفر

### المرحلة الأولى — اختبارات النسخ والاستعادة
الكود الأساسي موجود ولا نعيد كتابة BackupManager أو BackupArchive. المتبقي:
1. اختبار تكامل فعلي لـ SQLCipher وRestoreApplier من بداية الاستعادة حتى إعادة فتح قاعدة البيانات.
2. اختبارات استعادة بعد انقطاع/تعطل العملية في كل نقطة من نقاط الاستبدال المرحلي والتحقق من rollback.
3. اختبار اتساق قاعدة Room مع قاعدة MLS المنفصلة عند أخذ snapshot مع تغييرات مجموعة متزامنة.
4. تشغيل سلسلة migrations الفعلية على قواعد fixtures قديمة، وليس فقط التأكد من ترقيم migration IDs.
5. اختبار حالات فقد/تلف المرفقات وVault وملفات MLS وتفضيلات الخوادم وكلمة المرور الخاطئة والمساحة غير الكافية.

### تنسيق MLS
1. الموجود: owner-routed membership requests والمالك الوحيد الذي يكتب epoch.
2. المتبقي: تنسيق Proposal وفق RFC 9420 بين عدة مشرفين، وسياسة قبول/دمج/رفض المقترحات المتزامنة بصورة متوافقة مع OpenMLS.
3. المتبقي: معالجة fork/replay/conflicting commits بوضوح دون الكتابة على epoch متنافس.
4. اختبارات JVM/Rust للرفض وإعادة الإرسال وإعادة التشغيل، ثم اختبار interoperability على هاتفين في المرحلة العاشرة.

### المرحلة الثالثة — مؤجلة حسب ترتيب العمل
لا تبدأ الآن. العناصر المؤجلة فقط:
- DHT متعدد العقد واختبار publish/lookup فعلي بين عقد مستقلة.
- حفظ high-water mark لمنع replay/rollback لسجلات الحضور بعد إعادة التشغيل.
- توزيع/تكرار دليل المجتمعات عبر DHT بدل فهرس Pebble المحلي.
- تكامل TURN فعلي واختبار allocation وnonce/rate limits.
- سجل تشخيص لكل محاولة مسار مع النتيجة والمدة والسبب.
- Store-and-Forward عبر عقد طرف ثالث بموافقة وحدود تخزين وTTL وحذف.
- نشر عدة مشغلين للعقد وخوادم TURN؛ المستودع لا يشغل بنية عامة للمستخدمين.

## 5. بوابة قبول كل ميزة

لا تُسجل الميزة مكتملة إلا عند وجود:
- تنفيذ إنتاجي فعلي وليس واجهة أو تعريفًا فقط.
- ربط من واجهة التطبيق ومسار الاستخدام المناسب، مع حالات loading/empty/error/permission حيث يلزم.
- تخزين/تشفير/صلاحيات ودورة حياة Android صحيحة.
- اختبارات نجاح وفشل وتكرار واستعادة/إعادة تشغيل حسب طبيعة الميزة.
- موارد عربية وإنجليزية وتخطيط RTL.
- تحديث README والتوثيق الفني في نفس التغيير.
- CI أخضر على commit الذي يحتوي التنفيذ.
