# المرحلة الثامنة — الأدوات المرافقة في RELYRA

**حالة المصدر:** أُضيفت ملفات التنفيذ والربط واختبارات CI في هذا التغيير. لا تُعلن المرحلة مقبولة نهائيًا إلا بعد نجاح Workflow على الـ commit نفسه، ثم تشغيل المشغّل للأدوات على خادم مضبوط فعليًا. هذا لا يعني أن المستودع ينشر خادم RELYRA عامًا للمستخدمين.

## 1. Server Studio — إدارة خوادم RELYRA

المصادر: `companion/node/src/compose.mjs` و`companion/node/src/studio.mjs` و`companion/node/bin/relyra.mjs`.

الأداة تدير نشر Docker Compose الموجود أصلًا في `services/discovery/compose.yaml`، ولا تستبدل خدمة Go/libp2p ولا تنشئ خادمًا موازيًا.

الوظائف:
- إنشاء ملف إعداد المشغّل `.env`، وتوليد سر TURN عشوائي، وصلاحيات ملف مقيدة حيث يدعم النظام ذلك، ورفض الكتابة فوق إعداد موجود.
- ضبط عناوين bootstrap وannounce لعقد DHT بعد التحقق من عنوان IPv4 العام والمنفذ وصيغة Peer ID.
- قراءة حالة الخدمات وتشغيلها وإيقافها وإعادة تشغيلها وسحب صور الخدمات وإعادة بناء خدمة الاكتشاف من المصدر المحلي.
- قراءة آخر 200 سطر من سجلات Compose مع تنقيح قيم الأسرار المعروفة ورموز Bearer.
- إنشاء لقطات للـ named volumes والتحقق من SHA-256 وإدارتها واستعادتها بعد تأكيد صريح.
- قبل استبدال البيانات عند الاستعادة، تنشئ الأداة لقطة منفصلة للحالة الحالية وتحتفظ بها كخطة رجوع عند فشل الاستعادة.

لوحة التحكم في المتصفح تستمع على `127.0.0.1` فقط، وتستخدم رمز جلسة عشوائيًا محفوظًا في الذاكرة، وتضع الرمز في URL fragment الذي لا يُرسل في طلب HTTP، ثم تزيله من سجل المتصفح. تتحقق من Host وOrigin ونوع المحتوى وحجم الطلب ومعدل العمليات. تنتهي الجلسة بعد أربع ساعات.

**حدود مهمة:**
- الأداة لا تجهز DNS أو الجدار الناري أو تفتح منافذ عامة تلقائيًا.
- المشغّل هو المسؤول عن عنوان TURN العام، وشهادات HTTPS، والمنافذ، وبيانات bootstrap، ومراقبة الخدمة والاستجابة للحوادث.
- عقدة DHT واحدة ليست شبكة موزعة مقاومة لانقطاع العقد.
- نسخ Server Studio ليست مشفرة بكلمة مرور. تحتوي على بيانات volumes وقد تتضمن حالة حساسة. احفظ `.relyra-backups/` على قرص مشفر وبصلاحيات محدودة، واحتفظ بنسخة خارج الجهاز.
- ملف `.env` مستثنى من النسخ ويجب حفظه منفصلًا داخل مدير أسرار. لا ترفعه إلى GitHub.
- تنقيح السجلات يحجب قيم الأسرار المعروفة والتوكنات، لكنه لا يضمن اكتشاف سر يكتبه برنامج ما داخل نص عشوائي؛ يجب منع الخدمات من تسجيل المفاتيح وكلمات المرور أصلًا.

## 2. Desktop / Node Companion Tools

المجلد: `companion/node`.

تتطلب Node.js 20 أو أحدث، ولا تحتاج حزم npm خارجية وقت التشغيل. تشمل:
- أوامر CLI لإدارة الخدمات والنسخ والتهيئة المحلية.
- مكتبة `RelyraClient` للاتصال بواجهة Local API وقراءة الصحة والتشخيص والهوية العامة الاختيارية ووثيقة OpenAPI.
- ربط الحاسوب بتطبيق Android عن طريق ADB port forwarding عبر جلسة USB موثوقة.

واجهة تطبيق Android تظل مرتبطة بـ loopback فقط. أداة Node ترفض الاتصال بعناوين خارج loopback حتى لو كانت HTTPS، ولا تسمح إلا بمسارات القراءة الأربعة الموثقة. لا تستطيع إرسال رسائل أو قراءة محتوى المحادثات.

## 3. Developer Tools داخل تطبيق Android

أُضيف مدخل **أدوات المطور** إلى الإعدادات، وهو مربوط بحالة التطبيق الحقيقية:
- حالة Local API والمنفذ المحلي ووقت انتهاء الرمز المؤقت.
- إظهار الرمز أو نسخه، ونسخ أمر ADB forwarding.
- عدد مرحلات Nostr المضبوطة والمفعلة والمتصلة.
- حالة Mesh الحالية.
- الإضافات المثبتة والمفعلة وسجل نشاطها الوصفي المحدود، مع تفعيل/إيقاف الإضافة وحذفها بعد تأكيد المستخدم.
- فتح شاشة التشخيص الموجودة.

أُضيفت نقطتا API للقراءة فقط:
- `GET /v1/diagnostics`: مؤشرات تشغيل وأعداد وحالات منطقية منقحة؛ لا تعرض الرسائل أو المفاتيح الخاصة أو عناوين Relay أو قاعدة البيانات.
- `GET /v1/openapi.json`: عقد OpenAPI 3.1 لواجهة Local API.

تظل `/v1/health` و`/v1/identity` موجودتين. كل الطلبات تتطلب Bearer token عشوائيًا بطول 256 بت، صالحًا 15 دقيقة، وتلتزم بـ loopback وHost المتوقع وGET فقط ومنع جسم الطلب وحدود المعدل. قراءة الهوية العامة تظل اختيارية بصلاحية منفصلة. لا توجد عمليات كتابة.

## 4. الاختبارات وحدود التحقق

أضيف Job خاص بـ Node 22 في GitHub Actions لفحص سياسة عناوين API، ومسارات القراءة المسموح بها، والتحقق من عناوين DHT، وتنقيح السجلات، والاتصال المحلي الموثق. وأضيفت اختبارات JVM لـ LocalApiServer تتحقق من Bearer token والصحة والتشخيص وصلاحية قراءة الهوية ووثيقة OpenAPI.

لم أشغّل Gradle أو npm tests أو Docker أو نشر خادم يدويًا في هذه المهمة. نتيجة Workflow على الـ commit النهائي هي بوابة قبول الكود. أما تجربة إدارة خادم فعلي، وواجهة المتصفح، وربط هاتف حقيقي عبر ADB، ونسخ واستعادة بيانات نشر فعلي فتحتاج بيئة المشغّل ولا ندّعي أنها تحققت باختبارات الوحدات.

راجع [دليل Node Companion](../companion/node/README.md) للتثبيت وإعداد الخادم والعقد المتعددة والأوامر والنسخ الاحتياطي وADB. التفاصيل الإنجليزية: [Phase 8 — Companion tools](PHASE8_COMPANION_TOOLS.md).
