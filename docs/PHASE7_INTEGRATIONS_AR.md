# المرحلة السابعة — التكاملات في RELYRA

**الحالة:** منفذة جزئيًا على `main`. هذا المستند يصف ما هو موجود في المصدر فقط؛ لا يعني إنشاء الكود أنه بُني أو شُغّل أو خضع لاختبار أمني.

## 1. واجهة Local API

المصدر: `app/src/main/java/org/relyra/app/core/integrations/LocalApiServer.kt`.

- لا تبدأ تلقائيًا؛ المستخدم يشغّلها أو يوقفها من الإعدادات > التكاملات.
- تربط خادم HTTP بعنوان IPv4 loopback فقط `127.0.0.1` وعلى منفذ عشوائي مؤقت. لا يوجد استماع على LAN أو الإنترنت.
- تنشئ رمز Bearer عشوائيًا بطول 256 بت في الذاكرة فقط، وتنتهي صلاحيته بعد 15 دقيقة. إعادة التشغيل تنشئ منفذًا ورمزًا جديدين؛ إيقاف الخدمة يبطل الرمز فورًا.
- تقبل GET فقط، وترفض أجسام الطلبات، وتتحقق من Host وOrigin، وتفرض حدودًا على حجم وعدد الترويسات ومعدل الطلبات.
- `GET /v1/health`: حالة الخدمة وإصدار التطبيق والتوقيت.
- `GET /v1/identity`: الاسم ومعرّف RELYRA العام فقط، ولا يعمل إلا بعد تفعيل صلاحية قراءة الهوية من الشاشة.
- أضيف في المرحلة الثامنة `GET /v1/diagnostics` لقراءة أعداد وحالات تشغيل منقحة، و`GET /v1/openapi.json` لوصف العقد.
- لا تعرض الرسائل أو المرفقات أو مفاتيح التشفير أو محتويات قاعدة البيانات.
- لا توجد صلاحيات كتابة أو واجهة API لإرسال الرسائل أو إدارة المجموعات.

الرمز المؤقت سرّ محلي: لا تشاركه مع تطبيقات غير موثوقة. لا تُعد هذه الواجهة بديلًا عن مصادقة تطبيق/جهاز موثوق، ولا تعمل من جهاز آخر.

## 2. بيئة إضافات محدودة

المصدر: `core/integrations/PluginRuntime.kt` وشاشة `ui/screens/IntegrationsScreen.kt`.

هذه ليست بيئة تحميل كود عام أو Android DEX. إنها منفذ آمن نسبيًا لسير عمل Declarative بصيغة JSON، ويقبل فقط قائمة أوامر محددة:

- `notice`: عرض إشعار/رسالة داخل التطبيق.
- `copy_text`: نسخ نص إلى الحافظة، ويتطلب `clipboard.write`.
- `open_url`: فتح رابط HTTPS خارجي، ويتطلب `external.open`.

قواعد الحزمة:
- `schemaVersion: 1`، ومعرّف إضافة محدود الأحرف، وحجم أقصى 256 KiB.
- من 1 إلى 20 إجراءً، بمعرّفات فريدة، وحدود لطول النصوص والعناوين.
- أي صلاحية أو نوع إجراء خارج قائمة السماح يُرفض.
- يختار المستخدم ملف الإضافة، ويعاينه، ويراجع الصلاحيات المطلوبة، ثم يوافق صراحة على التثبيت. تُثبّت الإضافة معطلة، ويجب تفعيلها يدويًا.
- يمكن إيقاف الإضافة أو حذفها. الصلاحيات تُفحص مرة أخرى عند تشغيل كل إجراء.
- يسجل التطبيق محليًا آخر 100 عملية تثبيت/تفعيل/إيقاف/حذف/تنفيذ أو منع، من دون تخزين نصوص الأوامر المنسوخة أو بيانات خاصة.

مثال لحزمة بسيطة:

```json
{
  "schemaVersion": 1,
  "id": "example.notice",
  "name": "Example Notice",
  "version": "1.0.0",
  "description": "A local notice action",
  "permissions": [],
  "actions": [
    {
      "id": "show",
      "type": "notice",
      "title": "Show notice",
      "text": "Hello from a RELYRA workflow"
    }
  ]
}
```

لا تنفّذ الإضافات DEX أو Native code أو JavaScript أو shell أو ملفات تنفيذية. لذلك فهي لا تمثل بعد Plugin SDK عامًا أو sandbox لتشغيل شيفرات يكتبها المطورون. كما أن حزم JSON لا تحمل توقيع ناشر أو نظام تحديث موثوقًا؛ ثبّت فقط ما تثق بمصدره.

## 3. Matrix وXMPP/OMEMO

**تنفيذ عميلين تكامليين موجود في المصدر؛ جسر ترجمة شامل بين شبكات RELYRA وMatrix/XMPP غير مكتمل.**

### Matrix
المصدر: `MatrixRustE2eeClient.kt` مع Matrix Rust SDK الرسمي، ومربوط بشاشة التكاملات.
- تسجيل الدخول واستعادة جلسة Matrix وحفظ حالة الجلسة محليًا.
- إعداد مخزن SDK محلي مشفر بمفتاح قاعدة بيانات RELYRA المحمي، وتخزين بيانات الجلسة الحساسة بمساعدة Android Keystore.
- مزامنة الغرف والانضمام وإرسال الرسائل من خلال SDK.
- قبل الإرسال، يتحقق التطبيق من أن حالة تشفير الغرفة هي `ENCRYPTED`؛ ولا يحول الإرسال تلقائيًا إلى نص صريح عند غياب التشفير.
- لا يعني ذلك أن حساب RELYRA أصبح هوية Matrix أو أن رسائل RELYRA الفردية/الجماعية تُترجم وتُمرر تلقائيًا إلى Matrix.

### XMPP / OMEMO
المصدر: `XmppOmemoClient.kt` مع Smack 4.5.0.
- اتصال بخادم XMPP وتسجيل الدخول وإرسال رسائل OMEMO المشفرة واستقبال الرسائل وفك تشفيرها عند نجاح جلسة الطرفين.
- عرض بصمات أجهزة OMEMO، وقرارات الثقة/عدم الثقة، وعدم قبول الأجهزة المجهولة تلقائيًا.
- قرارات الثقة محفوظة مشفرة باستخدام Android Keystore.
- قيد أمني: مخزن مفاتيح OMEMO التشفيري نفسه ما زال في مساحة التطبيق الخاصة، ولا يصح الادعاء أن كل مفاتيح OMEMO محمية مباشرة بمفتاح Keystore.
- قيد ترخيص: `smack-omemo-signal` يعتمد على Signal provider بترخيص GPL-3.0؛ يجب إجراء مراجعة قانونية/ترخيصية قبل توزيع APK أو دمجه في إصدار يحمل Apache-2.0.

**بوابة التحقق:** لا يوجد في هذا المستند ادعاء بتوافق مُثبت مع خوادم مستقلة أو أجهزة خارجية. يجب فحص جلسات الدخول والتشفير وتبادل المفاتيح وإعادة الاتصال على خوادم اختبار حقيقية، ثم تنفيذ جسر الترجمة بين هويات ورسائل RELYRA والبروتوكولات الخارجية بصورة مستقلة قبل تسميته Bridge كاملًا.

## 4. IPFS

**عميل Kubo اختياري ومسار المرفقات المشفرة موجودان في المصدر.**
- يقبل التطبيق عنوان Kubo HTTPS RPC فقط، ويظل IPFS معطلًا ما لم يضبطه المستخدم.
- يمر الملف الصادر عبر تشفير RELYRA أولًا؛ ثم تُرفع بيانات ciphertext فقط إلى Kubo ويُستخدم CID في وصف النقل.
- يمكن استرجاع ciphertext من CID، والتحقق من الحجم وSHA-256 قبل تسليمه لمسار فك التشفير.
- رُبط المسار بمحرك نقل الملفات ومرفقات المجموعات؛ ويظل Blossom مسارًا بديلًا ولا يصبح IPFS شرطًا لتشغيل المراسلة الأساسية.

**حدود التحقق:** وجود كود Kubo لا يثبت توافر العقد أو pinning المستمر أو قابلية الوصول من شبكات عامة أو نجاح interoperability. هذه البنود تحتاج اختبار نشر وتشغيل منفصلًا.

## 5. ما تم ربطه وما لم يتم

| المكوّن | حالة المصدر |
|---|---|
| Local API | health وهوية اختيارية وdiagnostics وOpenAPI؛ القراءة فقط على loopback، ولا توجد صلاحيات كتابة |
| Plugin workflow runtime | موجود ومربوط بشاشة الإعدادات؛ ليس SDK لتشغيل كود عام |
| سجل الإضافات | سجل محلي محدود بآخر 100 حدث |
| Matrix client | عميل Rust SDK متصل بواجهة التكاملات؛ لا يمثل جسر رسائل RELYRA آليًا |
| XMPP/OMEMO | عميل Smack لإرسال/استقبال OMEMO وإدارة بصمات الثقة؛ تخزين مفاتيح OMEMO يحتاج مراجعة وحسم الترخيص |
| IPFS/Kubo | مسار ciphertext اختياري مرتبط بنقل المرفقات؛ التشغيل على عقد عامة لم يُتحقق منه |
| التوافق الخارجي | يحتاج اختبار خوادم Matrix/XMPP وKubo مستقلة؛ وعميل التكامل لا يساوي Bridge متعدد الشبكات |

**النتيجة:** المرحلة السابعة منفذة جزئيًا على مستوى المصدر: عميل Matrix وعميل XMPP/OMEMO ومسار IPFS للمرفقات موجودة بجانب Local API وبيئة إجراءات JSON. لم يُثبت بعد توافق الخوادم الخارجية، كما أن جسر الترجمة/تمرير الرسائل والهويات بين RELYRA وهذه الشبكات ليس مكتملًا. يلزم التحقق الآلي والتشغيلي ومراجعة الترخيص قبل إعلان المرحلة مكتملة.
