# RELYRA — خطة استكمال التنفيذ المرحلية

> هذه الخطة تفصل تنفيذ الميزات البرمجية عن اختبار الهواتف. لا تُعد أي ميزة مكتملة لمجرد وجود واجهتها أو تعريف بروتوكولها. لا تبدأ اختبارات الأجهزة الشاملة إلا بعد إنهاء المراحل البرمجية واجتياز CI.

## قواعد التنفيذ

1. العمل على فرع مستقل، مع الحفاظ على `main` دون تغييرات مباشرة أثناء التطوير.
2. قبل كل تغيير: مراجعة التنفيذ الحالي والواجهات وقاعدة البيانات والاختبارات؛ لا نكرر ميزة موجودة ولا ننشئ ملفات شكلية.
3. كل ميزة تُسلّم مع تنفيذ حقيقي، معالجة أخطاء، اختبارات آلية مناسبة، وتحديث التوثيق العربي والإنجليزي عند تأثرهما.
4. لا تُعرض وظائف غير منفذة على أنها تعمل. لا تُستخدم بيانات أو أزرار وهمية.
5. اختبارات الهواتف والتوافق بين أجهزة مستقلة وتأثيرات الشبكات الحقيقية مؤجلة إلى المرحلة الأخيرة.

## المرحلة 1 — إغلاق فجوات الأساس والبيانات

**الهدف:** جعل الوظائف الموجودة قابلة للاعتماد قبل إضافة طبقات جديدة.

- استكمال النسخ الاحتياطي والاستعادة لتشمل قاعدة البيانات وملفات المرفقات وVault ومفاتيح X3DH الخاصة وإعدادات التطبيق وخوادم Blossom القابلة للنقل.
- جعل النسخة الاحتياطية متسقة ذريًا: بيان محتويات، أحجام وحدود، تحقق من سلامة كل ملف، رفض المسارات غير الآمنة، وعدم استبدال البيانات الحالية قبل التحقق الكامل.
- معالجة استعادة جلسات التشفير القديمة: توضيح سياسة الاستعادة ومنع استئناف جلسة Ratchet بحالة قديمة على نحو يسبب فقدان الرسائل أو إعادة استخدام حالة غير آمنة.
- ضمان إعادة محاولة رفع Blossom بعد الانقطاع من الملف المشفر المحفوظ محليًا، مع إعادة التحقق من SHA-256 والحجم ووصف الخادم قبل اعتماد الرفع. بروتوكول Blossom الأساسي لا يعرّف استئنافًا بايتيًا للرفع؛ لا يُستخدم إلا عبر امتداد معلن ومدعوم من الخادم.
- إضافة اختبارات تسلسل ترحيلات قاعدة البيانات، الملفات المفقودة/التالفة وتغيير بصمتها، كلمة المرور الخاطئة، انقطاع النسخ، وفشل الكتابة عند امتلاء التخزين.

**معيار الإغلاق:** Android build واختبارات JVM وGo وRust ناجحة؛ اختبارات وحدات تغطي حالات الفشل المذكورة. اختبار الأجهزة لا يزال مؤجلًا.

## المرحلة 2 — إكمال المجموعات والمجتمعات

- تنسيق مقترحات MLS وتعارض تغييرات المشرفين دون السماح بكتابات Epoch متنافسة.
- بناء منشورات/تغذية مجتمعات فعلية مع توقيع المؤلف، تسلسل الأحداث، إزالة التكرار، والتحقق من صلاحيات النشر.
- تطبيق mute وslow mode وallow-post في مسار النشر نفسه، لا كأسماء أحداث فقط.
- استكمال دورة البلاغات: الحالة، المراجعة، القرار، سجل التدقيق، ومنع إساءة استخدام صلاحيات الإشراف.
- إضافة اختبارات تنافسية وإعادة تشغيل الحالة واختبارات صلاحيات.

**معيار الإغلاق:** اختبارات آلية تغطي تعدد المشرفين، ترتيب الأحداث، التكرار، الحظر، الدعوات، البلاغات، ومنع تجاوز الصلاحيات.

## المرحلة 3 — شبكة الإنترنت اللامركزية

- فصل واجهات Android عن بوابة HTTPS بحيث يمكن إضافة نقل libp2p أصلي لاحقًا دون كسر التطبيق.
- إكمال نشر واكتشاف عقد DHT متعددة، والتحقق من سجلات الحضور والتوقيع والانتهاء ومقاومة إعادة التشغيل.
- إكمال إدارة ICE/STUN/TURN، بيانات اعتماد مؤقتة، سياسات إعادة الاتصال، ومسارات fallback مع تسجيل المسار الفعلي.
- تصميم تخزين وترحيل الرسائل Store-and-Forward عبر عقد وسيطة بموافقة مالكي الأجهزة وحدود تخزين وعمر وحذف واضحة.
- توزيع دليل المجتمعات بدل الاعتماد على فهرس محلي وحيد.

**معيار الإغلاق:** اختبارات تكامل آلية بعقد متعددة وخوادم TURN تجريبية معزولة. اختبار الشبكات العامة والأجهزة مؤجل للمرحلة الأخيرة.

## المرحلة 4 — المكالمات الصوتية والمرئية

- إضافة WebRTC MediaTracks للصوت والفيديو؛ قناة DataChannel الحالية لا تُعد مكالمات.
- إشارات بدء/قبول/رفض/إنهاء المكالمة عبر رسائل RELYRA المشفرة.
- أذونات الميكروفون والكاميرا، اختيار الأجهزة، كتم الصوت، إيقاف الفيديو، حالات الاتصال، وإشعارات المكالمات.
- تشفير النقل وإدارة مفاتيح الجلسة، ومنع قبول عروض غير موثقة أو غير مصرح بها.
- اختبارات JVM/محاكاة للإشارات وحالات دورة الحياة، واختبارات تكامل قبل اختبار الهواتف النهائي.

**معيار الإغلاق:** دورة مكالمة كاملة قابلة للاختبار آليًا، مع حالات الفشل وإعادة الاتصال موثقة.

## المرحلة 5 — الهوية ومزامنة الأجهزة

- تسجيل جهاز جديد بموافقة جهاز موثوق قائم أو عبر استرداد آمن.
- قائمة الأجهزة، الإلغاء الفوري، تدوير المفاتيح، وربط هوية الحساب بمعرفات أجهزة منفصلة.
- مزامنة آمنة للرسائل والبيانات المسموح بها دون نسخ مفاتيح الجلسات الحساسة بطريقة غير آمنة.
- معالجة تعارضات التغييرات، حذف جهاز مفقود، وإعادة مزامنة جهاز جديد.
- اختبارات بروتوكول وتخزين وتعارضات آلية.

**معيار الإغلاق:** بروتوكول إضافة/إلغاء جهاز ومزامنة قابلة للتحقق آليًا قبل اختبار أجهزة حقيقية.

## المرحلة 6 — الشبكات القريبة والاتصال دون إنترنت

- إضافة Bluetooth LE عند الحاجة بدل الخلط بينه وبين Bluetooth Classic الموجود.
- تصميم Mesh متعدد القفزات مع مصادقة كل عقدة، حدود TTL وحجم وتخزين، منع الحلقات، وموافقة المستخدم.
- تنفيذ Store-and-Forward محليًا مع انتهاء صلاحية الرسائل وسياسة حذف وحماية من إساءة الاستخدام.
- اختبارات محاكاة للطوبولوجيا، انقطاع العقد، التكرار، والرسائل الخبيثة.

**معيار الإغلاق:** اختبارات محاكاة شبكية آلية؛ اختبار عدة هواتف مؤجل.

## المرحلة 7 — التكاملات والمنصة القابلة للتوسعة

- Matrix وXMPP/OMEMO عبر Bridges اختيارية مع بيان حدود التشفير بين الشبكات؛ لا ندّعي E2EE طرفًا لطرف عبر جسر لا يحافظ عليه.
- Plugin SDK/runtime مع صلاحيات محددة وعزل وواجهة موافقة وإيقاف؛ لا تحميل شيفرة غير موثوقة داخل عملية التطبيق.
- Local API اختيارية مع مصادقة محلية، رموز قصيرة العمر، صلاحيات لكل مورد، وحماية من CSRF/الوصول غير المصرح.
- IPFS تكامل اختياري لا يعتمد عليه تشغيل التطبيق الأساسي.
- اختبارات أمنية وصلاحيات وعزل لكل واجهة.

**معيار الإغلاق:** كل تكامل يعمل end-to-end في بيئة اختبار معزولة، أو يبقى موثقًا كغير منفذ ولا يظهر كميزة جاهزة.

## المرحلة 8 — Server Studio وDesktop/Developer Tools

- لوحة إدارة خدمات اختيارية تعرض الحالة الفعلية والسجلات والتكوين والتحقق من الصحة.
- أدوات سطح مكتب ومطور تتصل عبر واجهات موثقة، دون منحها وصولًا ضمنيًا إلى مفاتيح الهاتف.
- إعدادات نشر العقد، التحديث، النسخ الاحتياطي، والمراقبة مع حماية الأسرار.
- اختبارات حزم وتشغيل آلية لكل منصة مدعومة.

**معيار الإغلاق:** بناء وتشغيل الخدمات والأدوات في بيئة CI قابلة لإعادة الإنتاج.

## المرحلة 9 — تدقيق ما قبل اختبار الأجهزة

- مراجعة أمنية للتشفير وإدارة المفاتيح والتخزين والشبكة والصلاحيات.
- تدقيق RTL وإمكانية الوصول والترجمات.
- SBOM وتدقيق تراخيص الاعتماديات وإعدادات الإصدارات والتوقيع.
- مراجعة جميع عناصر المواصفات وربط كل عنصر بملف تنفيذ واختبار أو تصنيفه صراحةً كغير منفذ.

**معيار الإغلاق:** لا توجد ميزات معلنة دون تنفيذ واختبارات آلية، وCI أخضر بالكامل.

## المرحلة 10 — اختبار التطبيق على الهواتف الحقيقية

تبدأ هذه المرحلة فقط بعد اكتمال المراحل البرمجية السابقة. وتشمل تثبيت التطبيق على أكثر من جهاز، إنشاء هويات مستقلة، الرسائل الفردية والمجموعات، MLS، المرفقات والنسخ والاستعادة، المكالمات، الشبكات المحلية والإنترنت وNAT/TURN وTor، استهلاك الموارد، العمل بالخلفية، وإعادة التشغيل والتحديث. تُسجل كل مشكلة مع خطوات إعادة الإنتاج ثم تُصلح ويعاد الاختبار.
